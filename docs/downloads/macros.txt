# Optional printer macro installation

**Profiles work without these files on stock Sovol Zero 1.3.7 and 1.4.x.**
Install the macro pack once, even if you use multiple slicers. No MCU flash,
OTA or Klipper update is part of this installation.

## What each part needs

Every printer-side part builds on the macro pack in section 1. Only adaptive
preheat and the Spoolman check need the Python helpers in section 2.

| To use | You need | You do not need |
|---|---|---|
| The slicer profiles | The import in this download's README | Anything on the printer |
| The macro pack | Section 1: one firmware file, its include, and on 1.4.x the exhaust-fan edit | Python, precision mode |
| Precision mode | The macro pack, the mode file beside it, a Klipper restart after each rename, and the precision printer in the slicer: section 3 | Python, the Moonraker component |
| Automatic mode switching | Everything precision mode needs, plus the Moonraker component in section 3 | Python |
| Adaptive preheat and the Spoolman check | The macro pack, plus section 2 | Precision mode |

A job sliced with a precision printer is a precision print only when the
printer is in precision mode. Without the macro pack nothing checks:
`SVZERO_REQUIRE` is an unknown command, and the job prints at precision speeds
on the stock 16-microstep configuration. With the pack in standard mode the job
is refused before heating.

**Check what is active** by typing `SVZERO_MODE` in the console after each
restart:

| Reply | Means |
|---|---|
| `Unknown command:"SVZERO_MODE"` | The macro pack is not loaded: check its include in `printer.cfg` |
| `machine mode standard, automatic switching off` | The pack is loaded, in standard mode, with no Moonraker component |
| `machine mode precision, …` | Precision mode is active |
| `…, automatic switching on` | The Moonraker component is loaded and has seen Klipper start |

The Python helpers have loaded when `HELP` lists `CHAMBER_PREHEAT_WAIT` and
`SPOOL_GUARD`.

## 1. Install one native config

Back up `printer.cfg` and any files you will replace. From `optional-macros/`,
copy **one** of these files into `~/printer_data/config/svzero/`:

| Installed firmware | File to copy |
|---|---|
| 1.3.7 | `svzero-1.3.7.cfg` |
| 1.4.x (checked against 1.4.7) | `svzero-1.4.x.cfg` |

On **1.4.x**, comment out the **entire** stock `[temperature_fan exhaust_fan]`
section, including its options: the pack replaces that fan and chamber sensor,
and both definitions cannot claim the same pins. Keep `[fan_generic fan3]`.
No stock-section removal is needed on 1.3.7.

In `printer.cfg`, after Sovol's `[include Macro.cfg]` and all stock fan/sensor
definitions, but **before `SAVE_CONFIG`**, add the matching line:

```ini
# For 1.3.7, use this line:
[include svzero/svzero-1.3.7.cfg]
```

```ini
# For 1.4.x, use this line instead:
[include svzero/svzero-1.4.x.cfg]
```

Do not include both firmware files or the modular source configs as well.
The chosen file contains all native macros and hardware overrides. It needs no
added Python modules. Comments naming source files describe the Git source
layout; those files are already consolidated and are not extra installation steps.

Recheck that the printer is idle immediately before restarting Klipper;
a restart aborts an active print. Before printing, review the brush geometry
in the consolidated file's `nozzle_brush.cfg` section. Use `_BRUSH_STATUS` and
its documented `_BRUSH_TEACH`/dry-run procedure to commission your own clearances.
The supplied pad bounds were measured on one machine, not guaranteed for yours.

The native pack adds chamber exhaust regulation, a rear-sensor chamber wait,
material-aware wiping, positioned purge, cancellation and a bed cooldown ramp.
Without Python, there is no nozzle-air qualification, bed boost or early handover.
An unreachable chamber minimum still requires changing the request or cancelling.
The cooldown ramp changes the bed target; `_COOLDOWN_CONFIG ENABLE=0` disables it.
`COOLDOWN_ABORT` stops the ramp without turning heaters off; use `CANCEL_PRINT`
for shutdown and cancellation.

Nozzle growth compensation ships on for 1.3.7. It offsets the first layer for
the nozzle being hotter than when Z was referenced, with a coefficient
measured with the tare-tap on one Zero: about +0.09 mm farther from the bed
at 230 °C up to +0.14 mm at 280 °C. Each print logs one line with the
numbers. `SAVE_VARIABLE VARIABLE=nozzle_growth_mm_per_c VALUE=0` turns it off
on a machine; store your own measured value, in mm per °C, the same way.
Per-filament Z offsets tuned before become residuals: return them to 0 and
tune them again. On 1.4.x it is off, stock behaviour: k was measured with the
1.3.7 tare-tap and the eddy path has not been measured, so nothing is
applied. The consolidated config's `nozzle_growth.cfg` section
explains it, and the
[startup guide](https://github.com/rpcyan586/svzero-profiles/blob/main/docs/STARTUP.md#nozzle-growth-compensation)
covers measuring it.

## 2. Optional adaptive preheat and Spoolman

Skip this section to retain native-only behavior. To enable both enhancements:

1. Copy `chamber_preheat.py`, `spool_guard.py` and `moonraker.py` from
   `optional-macros/` into `~/klipper/klippy/extras/`, backing up any existing files.
2. Copy `optional-macros/svzero-python.cfg` into `~/printer_data/config/svzero/`.
3. Add this include after your firmware include, before `SAVE_CONFIG`:

```ini
[include svzero/svzero-python.cfg]
```

With the printer idle, restart the **Klipper service** to load the Python modules.
`RESTART` and `FIRMWARE_RESTART` do not reload an already-imported module.
Do not enable the include before installing all three modules; configured
Python sections with missing modules prevent Klipper from starting.

Adaptive preheat qualifies the stirred nozzle as a chamber-air observer. Bed boost
is on by default when the helper is installed; M191 ... BOOST=0 turns it off for
one wait. Early handover is bounded. A failed qualification or timeout remains an error. Spool guard checks
the active Spoolman spool before heating: absent integration is skipped with a
notice, while insufficient material or a configured integration's failure refuses
the print. See the consolidated config's comments for its explicit retry override.
To enable just one helper, use the individual feature configuration from Git;
the [advanced installation guide](https://github.com/rpcyan586/svzero-profiles/blob/main/INSTALL.md)
also covers separately configured fan/camera features.

## 3. Optional precision mode

Needs the macro pack from section 1. It does not need section 2.

1. Copy `svzero-mode-precision.cfg.off` into `~/printer_data/config/svzero/`,
   beside the firmware file, unchanged. The `.off` keeps the printer in
   standard mode. The firmware file includes `svzero-mode-*.cfg` from its own
   directory, so a mode file anywhere else is never read.
2. Add the precision printer in the slicer: `SV Zero Precision` in
   OrcaSlicer's printer selection, beside `SV Zero`, or
   `SV Zero Precision 0.4n` (and `0.3n`, `0.25n`, `0.2n`) in PrusaSlicer and
   SuperSlicer. It covers the 0.4, 0.3, 0.25 and 0.2 nozzles.
3. To enter precision mode, rename the file to `svzero-mode-precision.cfg` and
   restart Klipper while idle. To leave, rename it back and restart. A rename
   without a restart changes nothing; `SVZERO_MODE` says which mode is active.

A job sliced for the other mode is refused before heating, and the message
names the file to rename.

**Automatic switching** does that rename and restart for you. It needs step 1
done: the component switches modes by renaming that file, `.off` or not.

1. Copy `svzero_mode_switch.py` to `~/moonraker/moonraker/components/`.
2. Add a line `[svzero_mode_switch]` to `moonraker.conf`. If your firmware file
   is not in `svzero/`, add `mode_dir:` under it with that directory, relative
   to the config directory (`.` for beside `printer.cfg`).
3. Restart Moonraker. `SVZERO_MODE` should now end `automatic switching on`.

From then on a job sliced for the other mode is refused, the printer switches
once it is idle and cold, and the same job starts again.
`SVZERO_MODE MODE=precision` or `MODE=standard` switches with no job. The log is
`svzero_mode_switch.log`, beside Moonraker's.

## Updates and rollback

Replace the same consolidated file when updating; keep your personal tuning in
a separate config included last, before `SAVE_CONFIG`. Do not load source and
consolidated versions together. For a former modular installation, replace its
entry include with the consolidated one and remove duplicate source includes.

To remove Python, remove its include first and restart the Klipper service while
idle; the native fallback then takes over. To remove the native pack, remove its
include and restore any edited stock section (especially 1.4.x's exhaust fan),
or restore the backed-up configuration. Restart only when idle.

Keep the slicer's fallback skirt unless another priming sequence is in place.
Full source, builders, tests and optional feature configurations remain in the
[Git repository](https://github.com/rpcyan586/svzero-profiles).
